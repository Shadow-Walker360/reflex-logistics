# Architecture Decisions

This directory contains Architecture Decision Records (ADRs) for Reflex.

## Purpose

An ADR records an important engineering decision, including:

1. The problem
2. The options considered
3. The decision
4. The reasoning
5. The trade-offs
6. The consequences

## Examples

Future ADRs may cover:

- Why PostgreSQL was selected
- Why NestJS was selected
- Why the repository uses a monorepo
- Why Redis is used
- Why BullMQ is used
- Why Socket.IO is used
- How tenant isolation is implemented
- How delivery assignment works
- How payment failures are handled

## Principle

We document significant decisions so that future engineers can understand not only what Reflex does, but why it was designed that way.
